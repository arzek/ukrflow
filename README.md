# UkrFlow 🇺🇦

Голосовий диктант українською для macOS — аналог Wispr Flow, заточений під prompt engineering: надиктовуєте контекст і задачі голосом, отримуєте відполірований структурований prompt для Claude Code.

**Утримуєш праву Command (⌘) → говориш → відпускаєш → текст з'являється в активному застосунку.** Або вмикаєте **hands-free**: тап — старт, тап — стоп.

Клавішу можна змінити на будь-яку одним натисканням:

```bash
./run.sh --set-hotkey
```

Розпізнавання повністю локальне (Whisper large-v3-turbo через MLX, оптимізовано під Apple Silicon). Без інтернету, без підписок, без відправки голосу на сервери: модель живе в окремому локальному процесі на `127.0.0.1`, спільному для всіх профілів macOS (див. «Сервер STT»).

## Запуск

```bash
./run.sh
```

Перше диктування завантажить модель (~1.6 ГБ) з Hugging Face — далі все працює офлайн.

## Дозволи macOS (одноразово)

Застосунок працює від імені термінала, з якого його запущено (Terminal / iTerm / Warp). Йому потрібні три дозволи в **System Settings → Privacy & Security**:

1. **Microphone** — macOS запитає автоматично при першому записі.
2. **Input Monitoring** — щоб бачити утримання гарячої клавіші. Додайте свій термінал вручну, якщо не запитає.
3. **Accessibility** — щоб натискати Cmd+V за вас.

Після додавання дозволів перезапустіть термінал.

При автозапуску (`./install-autostart.sh`) процес — це вже не термінал, а `.venv/bin/python` проєкту. Якщо в `launchd.log` трапляється «стан клавіші не читається — вотчдог неактивний», цьому Python, найімовірніше, бракує **Input Monitoring** (System Settings → Privacy & Security → Input Monitoring → «+» → `~/ukrflow/.venv/bin/python`). Диктування працює й без цього, але вотчдоги, які рятують запис, коли macOS губить подію відпускання клавіші чи стоп-тап hands-free, тоді сліпі.

## Використання

- Утримуйте **гарячу клавішу** (за замовчуванням права Command ⌘) і говоріть — хоч 15 хвилин, обмежень немає. Відпустіть — текст обробиться і вставиться туди, де стоїть курсор.
- Стан видно в **menu bar**: 🎙 готовий → 🔴 запис (⏺ — hands-free) → ⏳ розпізнавання → ✨ шліфування → ✅ вставлено (⚠️ — збій, буде й системне сповіщення). Буква поруч — активний режим (P/C/R).
- Меню: **Режим**, **Бекенд**, перемикач **Hands-free (тап — старт, тап — стоп)**; **Почати запис** (hands-free запис без клавіші), **Зупинити запис**, **Скасувати запис** (без обробки й вставлення; аудіо лишається в `recordings/`), **Повторити останній запис**; **Сервер STT…** (стан сервера розпізнавання), **Зупинити сервер STT**; **Останній результат**, **Відкрити лог**, **Папка записів**, **Перезапустити UkrFlow**.
- Пунктуацію Whisper розставляє сам. Записи коротші за 0.4 с та тиша ігноруються. Комбінації з гарячою клавішею (Cmd+C, Cmd+Tab) диктуванням не вважаються.

## Hands-free

Меню → **Hands-free** (галочка зберігається в конфіг, діє з наступного запису):

- **Тап** основної клавіші — старт (⏺ і окремий звук трохи згодом: застосунок чекає, чи не буде другого тапу). **Ще один тап** будь-якої гарячої клавіші — стоп і вставлення.
- **Утримання** працює як завжди (push-to-talk) — і з увімкненим hands-free.
- **Подвійний тап** і далі перемикає режим; подвійний тап «за звичкою» одразу після стопу нового запису не почне.
- Клавіші режимів (див. нижче) тапом стартують hands-free одразу у своєму режимі.
- Забутий запис, у якому 120 с поспіль тиша (`hands_free_silence_stop_sec`, 0 — вимкнено), зупиняється сам. Це не ліміт тривалості — поки ви говорите, запис не обривається.
- Після автостопу тиші або перемикання профілю macOS у фон текст **не вставляється** (ви, найімовірніше, не дивитесь на екран): він у буфері обміну й у «Останньому результаті», прийде сповіщення «Текст у буфері — вставте Cmd+V».

## Режими

Клік по іконці → **Режим** → вибір із галочкою (зберігається в конфіг, діє з наступного диктування, при перемиканні приходить сповіщення):

| Режим | Що робить |
|---|---|
| **Raw** (R) | Тільки розпізнавання + словник, без LLM. Найшвидший |
| **Clean** (C) | Виправлення помилок, англіцизми латиницею, абзаци — формулювання автора недоторканні |
| **Prompt** (P) | Clean + prompt engineering: Markdown-структура «контекст → завдання → обмеження» для Claude Code (за замовч.) |

Кожен режим — це своя інструкція в `prompts/*.md` (редагуються на льоту) плюс будь-які перекриття конфігу (`polish`, модель, effort). Можна додавати власні режими прямо в `config.json`.

**Перемикання з клавіатури — подвійний тап основної клавіші** (правої ⌘): два швидкі натискання без утримання циклічно гортають режими (Prompt → Clean → Raw → …) зі сповіщенням і зміною букви в іконці. Тапи повністю тихі й не чіпають іконку — звук початку запису та червона іконка з'являються лише після того, як клавіша протрималась довше за поріг тапу (аудіо при цьому пишеться з першої мілісекунди, початок фрази не втрачається). Тап модифікатора сам по собі в macOS нічого не робить, тож конфліктів немає. Вимикається через `mode_cycle_double_tap: false`, пороги — `tap_max_sec` / `double_tap_gap_sec`.

Разове диктування в іншому режимі без перемикання — окрема клавіша режиму: призначте через `./run.sh --set-hotkey clean` (утримуєте її — диктуєте в clean, основна клавіша далі працює в липкому режимі).

## Надійність (довгі диктування не губляться)

- **Аудіо-буфер**: щойно запис зупинено, він зберігається в `recordings/*.wav` (останні 20) — ще до будь-якої обробки.
- **Аварійний журнал**: поки ви диктуєте, звук щосекунди дописується на диск (`recordings/*.pcm.part`). Якщо застосунок уб'ють чи перезапустять посеред 15-хвилинного диктування, при наступному старті журнал сам перетвориться на звичайний WAV і прийде сповіщення — далі меню → **Повторити останній запис**.
- **Розпізнавання**: якщо сервер STT зник чи перезапускається, запит автоматично повторюється; якщо сервер недоступний зовсім — запис розпізнається прямо в процесі UkrFlow (`stt_local_fallback`, повільніше, зате без втрат).
- **Шліфування**: збої повторюються (`retries`), а коли бекенд уперся в ліміт підписки — одразу пробується інший (`polish_fallback`). Якщо не вдалося і так — вставляється нешліфований текст: диктування ніколи не втрачається.
- **`./run.sh --retry`** — повторна обробка останнього збереженого запису з диска (після збою чи якщо закрили застосунок). З `--retry --mode prompt` можна перегнати запис іншим режимом — надиктували в raw, передумали → отримали структурований prompt без передиктовування. Після обробки є 3 с, щоб перемкнутись у потрібне вікно.
- **Поетапний лог** `ukrflow.log`: сирий текст Whisper пишеться одразу після розпізнавання, потім результат словника і відшліфований текст (або причина, чому шліфування нічого не змінило) — весь пайплайн можна переглянути й порівняти.

## Якщо щось зависло

Іконка лишилась 🔴/⏺, хоча клавішу відпущено, або застосунок не реагує на клавішу — усе лікується з меню, перезапускати вручну не треба:

1. **Зупинити запис** — завершує диктування звичайним шляхом: збереження → розпізнавання → шліфування → вставлення. **Скасувати запис** — те саме без обробки (аудіо лишається).
2. **Повторити останній запис** — переобробляє останній WAV із `recordings/` у поточному режимі, швидше за `./run.sh --retry`.
3. **Перезапустити UkrFlow** — піднімає процес наново. Незавершене диктування при цьому не губиться: воно скидається в аварійний журнал і відновлюється одразу після старту.

Те саме з термінала, якщо меню недоступне:

```bash
launchctl kickstart -k gui/$(id -u)/com.ukrflow.app
```

## Сервер STT

Whisper тримає ~2 ГБ RAM, тож модель живе не в кожному UkrFlow, а в одному процесі `ukrflow_server.py` на `127.0.0.1:47117` — спільному для всіх профілів macOS. UkrFlow піднімає його сам, щойно ви почали диктувати (модель вантажиться, поки ви говорите), а після 60 с простою сервер виходить і звільняє пам'ять; наступне диктування підніме його знову за кілька секунд (з локального кешу, без мережі). Запускати чи зупиняти його вручну не треба; стан — меню → **Сервер STT…**, лог — `server.log` у теці того профілю, що підняв сервер.

Якщо порт 47117 зайняв сторонній застосунок, прийде помилка з підказкою про `server_port`: перевірте, хто тримає порт (`lsof -nP -iTCP:47117 -sTCP:LISTEN`), задайте інший `server_port` у `config.json` — **однаковий в усіх профілях** — і перезапустіть UkrFlow.

### Два профілі macOS

У кожному профілі — свій клон `~/ukrflow` і свій автозапуск, а сервер розпізнавання — один на всіх. Після оновлення коду оновлюйте **обидва** клони (з кожного профілю):

```bash
git pull && .venv/bin/pip install -r requirements.txt
launchctl kickstart -k gui/$(id -u)/com.ukrflow.app
```

Якщо один клон відстав і версії несумісні, UkrFlow сам замінить чужий сервер своїм (у лозі буде порада оновити клон в іншому профілі).

## Покращення тексту

Шліфування виконує LLM за інструкцією активного режиму (`prompts/*.md`, див. «Режими» вище). Бекенди (`polish` у конфігу, режим може перекривати):

- `"codex"` (за замовч.) — **Codex CLI з вашою підпискою ChatGPT**, без API-ключів. Кожен виклик ізольований і не зберігає сесію. Модель та effort налаштовуються через `polish_codex_model` / `polish_codex_effort`.
- `"claude-code"` — **Claude Code CLI з вашою підпискою**, без API-ключів. Запускається `claude -p` з `--no-session-persistence` (сміттєві сесії не зберігаються), у `--safe-mode` (ваші хуки, плагіни, skills і CLAUDE.md не втручаються у шліфування), без інструментів, slash-команд, MCP-серверів і зайвого трафіку. Модель та effort — `polish_claude_code_model` / `polish_claude_code_effort` (`--effort low` ≈ 3–10 с на диктування).
- `"off"` — без шліфування.

Для швидкого перемикання натисніть іконку UkrFlow у menu bar → **Бекенд** → **Codex (ChatGPT)** або **Claude Code**. Галочка та вибір у `config.json` оновлюються одразу; перезапуск не потрібен. Зміна діє з наступного диктування. Режим **Raw** завжди лишається без LLM незалежно від вибраного бекенда.

Коли основний бекенд не впорався чи вперся в ліміт підписки, текст шліфує інший (`polish_fallback`: `"auto"` — інший із пари codex/claude-code, `"off"` — без запасного, або назва бекенда); про ліміт прийде сповіщення. Зовсім короткі фрази (< 25 символів, поріг `polish_min_chars`) не шліфуються заради швидкості.

Додаткові необов'язкові рівні (обидва порожні за замовчуванням — наповнюйте своїм словниковим запасом):

- `dictionary.json` — миттєві точні заміни без LLM, формат `{"джира": "Jira"}`.
- `initial_prompt` у конфігу — допишіть свої терміни латиницею, і Whisper одразу писатиме їх латиницею (це словниковий байас розпізнавання, а не інструкція).

Щоб обрати модель шліфування за швидкістю й якістю на власних диктуваннях, є `bench_polish.py` (результати — у `runs/`). Кожен його виклик — справжній запит до Codex/Claude і витрачає квоту підписок, тому спершу дивіться план: `.venv/bin/python bench_polish.py --dry-run`.

## Налаштування — `config.json`

Файл створюється при першому запуску:

| Ключ | Значення |
|---|---|
| `hotkey` | Гаряча клавіша: `cmd_r` (за замовч.), `ctrl_r`, `alt_l`, `f13`, `vk:NN`… Найпростіше обрати через `./run.sh --set-hotkey`. Рекомендуються модифікатори (⌘⌥⌃⇧) — звичайні клавіші під час утримання друкують символи. Клавішу fn/🌐 перехопити неможливо |
| `hands_free` | Hands-free: тап — старт, тап — стоп (`false`; перемикач у меню) |
| `hands_free_silence_stop_sec` | Автостоп забутого hands-free запису після стількох секунд тиші (`120`, `0` — вимкнено) |
| `model` | `mlx-community/whisper-large-v3-turbo` (за замовч.). Швидша, але менш точна: `mlx-community/whisper-medium-mlx` |
| `initial_prompt` | Підказка моделі — допишіть сюди свої терміни, імена, абревіатури, щоб Whisper їх краще впізнавав |
| `polish_fallback` | Запасний бекенд шліфування: `"auto"` (за замовч.), `"off"` або назва |
| `server_port` | Порт сервера STT на `127.0.0.1` (`47117`) — однаковий в усіх профілях |
| `server_idle_sec` | Через скільки секунд простою сервер STT виходить (`60`) |
| `server_ready_timeout_sec` | Скільки чекати, поки щойно запущений сервер відповість (`10`) |
| `stt_local_fallback` | Розпізнавати в самому UkrFlow, якщо сервер недоступний (`true`) |
| `append_space` | Пробіл після вставленого тексту (`true`) |
| `restore_clipboard` | Відновлювати буфер обміну після вставлення (`true`). Увага: відновлюється лише текст — картинка в буфері загубиться |
| `input_device` | Індекс мікрофона (`null` = системний). Список: `.venv/bin/python -m sounddevice` |

## Встановлення на іншому Mac

Скопіюйте папку `ukrflow` без `.venv`, `recordings`, `ukrflow.log` і `server.log` (або запуште в git — ці шляхи вже в `.gitignore`) і виконайте:

```bash
./install.sh
./run.sh
```

Потрібні: Apple Silicon (M1+), Python 3 і хоча б один залогінений CLI для шліфування — Codex або Claude Code. Модель завантажиться при першому диктуванні. Для Intel-Mac замініть `mlx-whisper` на `faster-whisper` (потребує правок у `ukrflow_server.py`).

## Якщо текст не вставляється автоматично

Це завжди означає, що терміналу бракує дозволу **Accessibility** — macOS мовчки ігнорує синтетичний Cmd+V. Застосунок при старті сам відкриє потрібну панель налаштувань; далі:

1. System Settings → Privacy & Security → **Accessibility**.
2. Натисніть «+», додайте застосунок термінала, з якого запускаєте UkrFlow (Terminal / iTerm / Warp), і ввімкніть перемикач.
3. **Повністю перезапустіть термінал** (Cmd+Q, не просто закрити вкладку) і запустіть `./run.sh` знову.

Поки дозволу немає, розпізнаний текст кладеться в буфер обміну — його можна вставити вручну через Cmd+V.

## Як це працює

`pynput` слухає гарячу клавішу → `sounddevice` пише звук з мікрофона (16 кГц) → WAV на диск → локальний сервер STT (`ukrflow_server.py`, `mlx-whisper` з примусовою мовою `uk`) повертає текст → словник замін → LLM-шліфування (Codex CLI / Claude Code CLI) → текст кладеться в буфер обміну і вставляється синтетичним Cmd+V, після чого буфер відновлюється.
