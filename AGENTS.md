# AGENTS.md

Інструкції для Codex під час роботи з цим репозиторієм. Файл лежить у корені й
застосовується до всього проєкту.

## Що це

UkrFlow — голосовий диктант українською для macOS (аналог Wispr Flow),
заточений під prompt engineering: користувач утримує гарячу клавішу, диктує
(хоч 10–15 хв), текст локально розпізнається, шліфується LLM-кою і вставляється
в активний застосунок. Уся логіка — в одному модулі `ukrflow.py`. Потрібен
Apple Silicon (MLX).

## Команди

```bash
./run.sh                      # запуск (menu bar + глобальний слухач клавіш)
./run.sh --set-hotkey         # калібрування основної клавіші (натисканням)
./run.sh --set-hotkey clean   # окрема клавіша разового диктування в режимі
./run.sh --retry [--mode X]   # переобробити останній запис із recordings/
./install.sh                  # встановлення на новому Mac (venv + залежності)
./install-autostart.sh        # автозапуск при вході в систему (LaunchAgent)
./uninstall-autostart.sh      # вимкнути автозапуск і зупинити процес
```

Автозапуск: LaunchAgent `com.ukrflow.app` викликає `.venv/bin/python ukrflow.py`
**напряму** (не через `run.sh`) з `WorkingDirectory`. Проєкт **мусить лежати
поза теками, захищеними TCC** (Desktop/Documents/Downloads): при вході в систему
launchd/xpcproxy не може читати їх вміст — `posix_spawn` падає з «Operation not
permitted» ще до старту Python, і жодні дозволи Python це не обходять (з
термінала при цьому все працює — саме тому збій видно лише після
перезавантаження). Тому проєкт фізично живе в `~/ukrflow`, а
`~/Desktop/ukrflow` — симлінк для зручності; `install-autostart.sh` пише в plist
фізичні шляхи (`pwd -P`) і відмовляється встановлюватись із захищеної теки.
`KeepAlive.SuccessfulExit=false` — перезапуск після збою, але не після ручного
Quit. Перед ручним `./run.sh` агент зупиняти (`./uninstall-autostart.sh` або
`launchctl bootout`), інакше два екземпляри б'ються за клавіші й мікрофон;
перезапуск після зміни коду:
`launchctl kickstart -k gui/$(id -u)/com.ukrflow.app`.

Тестового фреймворку немає — перевірки виконуються ad-hoc скриптами через
`.venv/bin/python` (див. «Конвенції тестування» нижче). Синтаксис:
`.venv/bin/python -c "import ast; ast.parse(open('ukrflow.py').read())"`.

## Архітектура

### Пайплайн диктування

```text
pynput (утримання клавіші) → sounddevice 16 кГц → WAV у recordings/ (ДО обробки!)
  → mlx_whisper (language="uk") → словник dictionary.json (точні заміни)
  → LLM-шліфування за активним режимом → буфер обміну + синтетичний Cmd+V
```

Ключові рішення, які легко зламати ненавмисно:

- **Аудіо зберігається на диск до будь-якої обробки** (`save_recording` у
  `stop_recording`) — це гарантія, що 15-хвилинне диктування не втрачається за
  жодного збою. Не переносити збереження пізніше по пайплайну.
- **Cmd+V надсилається через Quartz за фізичним кодом клавіші** (`send_cmd_v`,
  keycode 9), а не символом — інакше ламається з активною українською
  розкладкою.
- **Без дозволу Accessibility** macOS мовчки ігнорує синтетичний Cmd+V; код
  перевіряє `AXIsProcessTrusted` і в такому разі лишає текст у буфері та не
  відновлює старий вміст.
- Збій шліфування (після retry) → вставляється нешліфований текст. Диктування
  ніколи не блокується і не губиться.
- Кожен етап пишеться в `ukrflow.log` одразу (`log_block`), а не одним записом
  наприкінці.

### Режими

`config["modes"]` — словники, що перекривають базовий конфіг на час одного
диктування через `effective_config()`. Кожен режим = файл інструкції в
`prompts/*.md` (перечитується перед кожним викликом — редагується наживо) +
довільні перекриття (`polish`, модель, effort). Липкий режим — `config["mode"]`;
перемикається з меню в menu bar, подвійним тапом основної клавіші (цикл за
порядком у словнику) або разовими клавішами режимів (`mode["hotkey"]`).

Стандартні режими: `raw` (`polish: off`), `clean` (виправлення без переробки),
`prompt` (prompt engineering, типовий).

### Бекенди шліфування (`POLISH_BACKENDS`)

- `codex` (типовий) — subprocess `codex exec` з підпискою ChatGPT. Виклик
  ізольований через `--ephemeral`, `--ignore-user-config`, `--ignore-rules`,
  `--sandbox read-only` та окрему порожню тимчасову теку; фінальна відповідь
  читається з `--output-last-message`. Не прибирати ці обмеження: процес
  шліфування не повинен бачити проєкт, запускати інструменти або зберігати сесію.
- `claude-code` — subprocess `claude -p` з підпискою користувача. Критичні
  прапорці: `--no-session-persistence`, `--effort low`, `--strict-mcp-config` з
  порожнім набором і `--disallowed-tools "*"`. `--bare` не використовувати — він
  пропускає OAuth.
- `local` — Qwen3-8B через mlx-lm (офлайн, слабший).
- `api` — anthropic SDK, потребує `ANTHROPIC_API_KEY`.

Базовий бекенд — `config["polish"]`; він перемикається наживо через підменю
«Бекенд» і діє з наступного диктування. Режим може перекривати його (стандартний
`raw` завжди задає `polish: off`).

### Потоки

Головний потік — rumps (GUI menu bar); слухач pynput і прогрів — фоновий потік;
кожне диктування обробляється в daemon-воркері (`_process_safely` — обгортка, що
перетворює будь-який виняток на ⚠️ + сповіщення + підказку `--retry`). Будь-які
оновлення GUI (титул іконки, галочки меню) — лише через
`NSOperationQueue.mainQueue()`. `StatusIndicator` без прикріпленого GUI — no-op
(так працюють `--retry` і тести).

### Подвійний тап і відкладений фідбек

Тап = натискання коротше `tap_max_sec` (0.35 с). Аудіопотік стартує з першої
мілісекунди натискання, але звук початку і 🔴 з'являються лише після порогу тапу
(`_confirm_recording` через `threading.Timer`) — тому тапи тихі й не миготять
іконкою. Не повертати «миттєвий» фідбек: це свідоме UX-рішення.

## Конвенції

- **Усе українською**: коментарі, повідомлення в консоль, документація. Виняток
  — назви пунктів меню macOS в інструкціях для користувача пишуться англійською
  (`System Settings → Privacy & Security`), бо macOS користувача англомовна.
- **Жодного хардкоду словників/термінів**: `dictionary.json` та `initial_prompt`
  порожні/нейтральні за замовчуванням — їх наповнює користувач. Інструкції LLM
  живуть у `prompts/*.md` як дані, а не в коді.
- `load_config()` мерджить `DEFAULT_CONFIG` з `config.json` і записує результат
  назад — нові ключі з'являються у файлі автоматично. `config.json` — живий стан
  користувача (поточний режим, клавіші): не перезаписувати його значення
  дефолтами й не змінювати під час тестів.
- Диктування на 10–15 хвилин — норма: не зменшувати 600-секундні таймаути
  Codex/Claude CLI й `max_tokens=16000` для API.
- Перед змінами перевіряти `git status` і зберігати всі сторонні незакомічені
  зміни користувача.

## Конвенції тестування

- Перевірки — інлайн-скрипти через `.venv/bin/python` з підміною
  важких/побічних частин: `ukrflow.sd.InputStream` → заглушка,
  `ukrflow.play_sound` → колектор, `app.paste` → заглушка (**ніколи не викликати
  справжній `paste` у тестах** — він перезапише буфер обміну користувача і
  натисне Cmd+V в активному вікні).
- Не лишати тестові WAV у `recordings/` (`--retry` бере останній файл) і не
  змінювати `config["mode"]` користувача — підміняти `set_mode`/`save_config` або
  чистити за собою.
- Наскрізний тест розпізнавання: згенерувати українське аудіо голосом Lesya
  (`say -v Lesya -o t.aiff …` + `afconvert -f WAVE -d LEI16@16000 -c 1`),
  завантажити через `scipy.io.wavfile` і передати numpy-масив у `process_audio`
  (шлях-аргумент для mlx_whisper потребував би ffmpeg — його немає).
- GUI-частину rumps неможливо перевірити headless — після змін у `run()`/меню
  перевіряти лише імпорт і логіку, решту віддавати користувачу на ручний запуск.
