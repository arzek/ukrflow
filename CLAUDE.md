# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Що це

UkrFlow — голосовий диктант українською для macOS (аналог Wispr Flow), заточений під prompt engineering: користувач утримує гарячу клавішу, диктує (хоч 10–15 хв), текст локально розпізнається, шліфується LLM-кою і вставляється в активний застосунок. Уся логіка — в одному модулі `ukrflow.py`. Потрібен Apple Silicon (MLX).

## Команди

```bash
./run.sh                      # запуск (menu bar + глобальний слухач клавіш)
./run.sh --set-hotkey         # калібрування основної клавіші (натисканням)
./run.sh --set-hotkey clean   # окрема клавіша разового диктування в режимі
./run.sh --retry [--mode X]   # переобробити останній запис із recordings/
./install.sh                  # встановлення на новому Mac (venv + залежності)
```

Тестового фреймворку немає — перевірки виконуються ad-hoc скриптами через `.venv/bin/python` (див. «Конвенції тестування» нижче). Синтаксис: `.venv/bin/python -c "import ast; ast.parse(open('ukrflow.py').read())"`.

## Архітектура

### Пайплайн диктування

```
pynput (утримання клавіші) → sounddevice 16 кГц → WAV у recordings/ (ДО обробки!)
  → mlx_whisper (language="uk") → словник dictionary.json (точні заміни)
  → LLM-шліфування за активним режимом → буфер обміну + синтетичний Cmd+V
```

Ключові рішення, які легко зламати ненавмисно:

- **Аудіо зберігається на диск до будь-якої обробки** (`save_recording` у `stop_recording`) — це гарантія, що 15-хвилинне диктування не втрачається за жодного збою. Не переносити збереження пізніше по пайплайну.
- **Cmd+V надсилається через Quartz за фізичним кодом клавіші** (`send_cmd_v`, keycode 9), а не символом — інакше ламається з активною українською розкладкою.
- **Без дозволу Accessibility** macOS мовчки ігнорує синтетичний Cmd+V; код перевіряє `AXIsProcessTrusted` і в такому разі лишає текст у буфері та не відновлює старий вміст.
- Збій шліфування (після retry) → вставляється нешліфований текст. Диктування ніколи не блокується і не губиться.
- Кожен етап пишеться в `ukrflow.log` одразу (`log_block`), а не одним записом наприкінці.

### Режими

`config["modes"]` — словники, що перекривають базовий конфіг на час одного диктування через `effective_config()`. Кожен режим = файл інструкції в `prompts/*.md` (перечитується перед кожним викликом — редагується наживо) + довільні перекриття (`polish`, модель, effort). Липкий режим — `config["mode"]`; перемикається з меню в menu bar, подвійним тапом основної клавіші (цикл за порядком у словнику) або разовими клавішами режимів (`mode["hotkey"]`).

Стандартні режими: `raw` (polish off), `clean` (виправлення без переробки), `prompt` (prompt engineering, типовий).

### Бекенди шліфування (`POLISH_BACKENDS`)

- `claude-code` (типовий) — subprocess `claude -p` з підпискою користувача. Критичні прапорці: `--no-session-persistence` (користувач принципово не хоче сміттєвих сесій), `--effort low` (без нього виклик ~60 с замість 3–10 с), `--strict-mcp-config` з порожнім набором (інакше вантажаться MCP-сервери користувача). `--bare` не використовувати — він пропускає OAuth.
- `local` — Qwen3-8B через mlx-lm (офлайн, слабший).
- `api` — anthropic SDK, потребує `ANTHROPIC_API_KEY`.

### Потоки

Головний потік — rumps (GUI menu bar); слухач pynput і прогрів — фоновий потік; кожне диктування обробляється в daemon-воркері (`_process_safely` — обгортка, що перетворює будь-який виняток на ⚠️ + сповіщення + підказку `--retry`). Будь-які оновлення GUI (титул іконки, галочки меню) — лише через `NSOperationQueue.mainQueue()`. `StatusIndicator` без прикріпленого GUI — no-op (так працюють `--retry` і тести).

### Подвійний тап і відкладений фідбек

Тап = натискання коротше `tap_max_sec` (0.35 с). Аудіопотік стартує з першої мілісекунди натискання, але звук початку і 🔴 з'являються лише після порогу тапу (`_confirm_recording` через `threading.Timer`) — тому тапи тихі й не миготять іконкою. Не повертати «миттєвий» фідбек: це свідоме UX-рішення.

## Конвенції

- **Усе українською**: коментарі, повідомлення в консоль, документація. Виняток — назви пунктів меню macOS в інструкціях для користувача пишуться англійською (System Settings → Privacy & Security), бо macOS користувача англомовна.
- **Жодного хардкоду словників/термінів**: `dictionary.json` та `initial_prompt` порожні/нейтральні за замовчуванням — їх наповнює користувач. Інструкції LLM живуть у `prompts/*.md` як дані, а не в коді.
- `load_config()` мерджить `DEFAULT_CONFIG` з `config.json` і записує результат назад — нові ключі з'являються у файлі автоматично. `config.json` — живий стан користувача (поточний режим, клавіші): не перезаписувати його значення дефолтами.
- Диктування на 10–15 хвилин — норма: не додавати часових лімітів (таймаут claude CLI — 600 с, api `max_tokens` — 16000).

## Конвенції тестування

- Перевірки — інлайн-скрипти через `.venv/bin/python` з підміною важких/побічних частин: `ukrflow.sd.InputStream` → заглушка, `ukrflow.play_sound` → колектор, `app.paste` → заглушка (**ніколи не викликати справжній `paste` у тестах** — він перезапише буфер обміну користувача і натисне Cmd+V в активному вікні).
- Не лишати тестові WAV у `recordings/` (`--retry` бере останній файл) і не змінювати `config["mode"]` користувача — підміняти `set_mode`/`save_config` або чистити за собою.
- Наскрізний тест розпізнавання: згенерувати українське аудіо голосом Lesya (`say -v Lesya -o t.aiff …` + `afconvert -f WAVE -d LEI16@16000 -c 1`), завантажити через `scipy.io.wavfile` і передати numpy-масив у `process_audio` (шлях-аргумент для mlx_whisper потребував би ffmpeg — його немає).
- GUI-частину rumps неможливо перевірити headless — після змін у `run()`/меню перевіряти лише імпорт і логіку, решту віддавати користувачу на ручний запуск.
